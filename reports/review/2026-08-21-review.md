## Findings

### F-007 — A promotion to MICRO_CAPITAL can be recorded with no evidence whatsoever — **Critical**

**Claim.** `review_artifact` enforces a reviewer, a written justification, a
semantic subject version and a legal transition. It does not require, accept by
name, or check for any evidence. The one sentence in the constitution that
governs what a promotion must rest on is implemented by nothing.

**Evidence.** `framework/artifacts/review.py:70-84` — the signature takes
`justification`, `confidence_adjustment`, `resulting_confidence`, `resizing_note`
and `sections`; there is no `evidence` parameter and no `relationships`
parameter. `framework/artifacts/review.py:131-136` — the only check on the
substance of the decision is that `justification.strip()` is non-empty.
`framework/artifacts/review.py:167-174` — the factory call passes `identifier`,
`title`, `artifact_type`, `author` and `content`, and nothing else but `**kwargs`.
`tests/artifacts/test_review_decision.py` (407 lines, 21 tests) contains the
string "evidence" zero times. Run against the repository as committed:

```
review_artifact(identifier="REV-0001", subject_id="STRAT-0001",
                subject_version="1.0.0", reviewer="me",
                outcome=ReviewOutcome.PROMOTE,
                stage_at_review=StrategyLifecycle.PROMOTION_REVIEW,
                resulting_stage=StrategyLifecycle.MICRO_CAPITAL,
                justification="Looks good.",
                confidence_adjustment=ConfidenceAdjustment.NO_CHANGE)

outcome        : Promote -> Micro Capital
justification  : Looks good.
evidence       : ()
evidence_level : None
relationships  : ()
validates      : True
saved          : 1.0.0.yaml
```

The contrast with the sibling guards is the finding. The same file refuses a
blank reviewer, a blank justification, a non-semantic subject version, a
promotion that descends the ladder, a demotion that climbs it, a retirement
recorded as a demotion, and a confidence outside [0, 1] — every one of them a
*form* check. The one *substance* check the constitution actually names is absent.

**Breach.** `constitution/Paper_First_Capital_Doctrine.md:45-47` — "Promotion
requires evidence. Never confidence alone." Also
`constitution/Immutable_Laws.md:23-25` (Law III, capital must be earned) and
`constitution/Immutable_Laws.md:15-17` (Law II, every investment decision must be
explainable — a REVIEW artifact with an empty `relationships` tuple cannot
produce, after the fact, the artifact its decision rested on). The phrase
"Promotion requires evidence" appears in exactly one file in the repository —
`grep -rn "requires evidence" --include=*.md .` returns
`constitution/Paper_First_Capital_Doctrine.md:45` and nothing else. No ADR cites
it; ADR-009 (`docs/DECISIONS.md:1060`) rules the review record and never mentions
evidence.

**Failure.** Stage 3 lands. A backtest produces a Sharpe and a p-value as signed
metric artifacts. A reviewer reads them, is convinced, and records the promotion
through the one sanctioned path. The REVIEW artifact stores the reviewer's prose
and stores *no pointer to the artifacts they read*. Three months later the
strategy is down and the question is "what did we see". `review_fields()` returns
"Looks good." The metric artifacts may still exist in `artifacts/`, but nothing
links them to this decision, and nothing ever required that they existed at all —
the identical record could have been written before any backtest was run. This is
not a hypothetical divergence between two documents; it is the audit trail Law II
requires, absent by construction.

**Proposal.** Require evidence on a movement outcome. The smallest version:
`review_artifact` takes a required `evidence: tuple[EvidenceRecord, ...]` (or
`supporting: tuple[str, ...]` of artifact identifiers written into
`relationships`) and raises when `outcome` is `PROMOTE` and it is empty — the same
shape as the `justification` refusal directly above it at
`framework/artifacts/review.py:131`. `REMAIN_CURRENT_STAGE` and `RETIRE` may
reasonably be exempt; `PROMOTE` may not. A conformance test parsing
`Paper_First_Capital_Doctrine.md:45` the way
`tests/test_governance_conformance.py:454` already parses the same file's stage
sequence would stop the sentence being implementable-and-unimplemented again.

### F-008 — The factory's stated defence of the deserialization path is false; a re-hashed hand-edit reaches PRODUCTION through `get()` — **High**

**Claim.** F-001's fix closes the factory. The comment justifying why that is
*sufficient* asserts a guarantee the integrity mechanism cannot provide: the hash
is an unkeyed SHA256, so anyone who can edit the file can recompute it, and a
hand-edited capital stage survives both `ArtifactRepository.get()` and
`ArtifactValidator.validate()`.

**Evidence.** `framework/artifacts/factory.py:56-60` states it verbatim:
"Reconstruction at a later stage is not this path's job — `ArtifactSerializer.load()`
builds `Artifact(...)` directly, and the repository verifies the integrity hash
on read, so a stage that was earned survives the round trip **while a
hand-edited one does not**." `framework/artifacts/primitives.py:44-46` —
`canonical_digest` is `hashlib.sha256(json.dumps(...))`. No key, no secret, no
signature: "signed" in this codebase means "checksummed". Run against the
repository as committed:

```
1. factory PRODUCTION birth: refused -- a strategy cannot be created at stage
   <StrategyLifecycle.PRODUCTION: 'Production'> ...            <- F-001 fix holds
2. saved at stage StrategyLifecycle.IDEA
3. naive hand-edit -> get() refused: integrity hash does not match its contents
4. re-hashed hand-edit -> get() returned stage: StrategyLifecycle.PRODUCTION
   verify_hash: True
   ArtifactValidator().validate: True
5. Artifact(...)+sign direct: stage PRODUCTION, validate True, save ok True
```

Step 4 is the finding: `ArtifactSerializer.load()` the edited YAML,
`ArtifactIntegrity.sign()` it — the same public call the factory makes — write it
back, and `get()` returns a PRODUCTION strategy that verifies. Step 5 shows the
shorter route: `Artifact(...)` plus `sign()` bypasses the factory entirely, which
`framework/artifacts/factory.py:12-16` acknowledges is a convention ("Producers
… **should** build artifacts here") rather than a mechanism.

**Breach.** `constitution/Evidence_Standards.md:45` — "Every conclusion must
reference supporting evidence." The comment states a security property as
established fact with no support, in the exact place a future reader will consult
to decide whether F-001 is fully closed. Also
`constitution/Paper_First_Capital_Doctrine.md:5-7`, which is what the false
comfort is protecting.

**Failure.** *Prediction, and the realistic route is not malice.* The next session
needs to reconstruct a strategy at a stage it genuinely earned — a migration, an
import, a repaired file. The factory refuses. The comment tells them the
deserializer is the sanctioned path for exactly this and that integrity will
catch anything hand-edited. They write the loader-plus-re-sign helper, it works,
it is committed, and the only guard on birth stage becomes optional. The audit
trail that would expose it is the REVIEW chain, which F-007 shows is not required
to exist.

**Proposal.** Correct the comment first — it is one sentence and it is currently
false. `framework/artifacts/factory.py:58-60` should say what the mechanism
actually gives: the hash detects *accidental* corruption and edits by anyone who
does not re-sign, and it is not a signature. Then, if reconstruction at a later
stage is genuinely needed, name that path explicitly and make it take the review
chain that justifies the stage, as F-001's own proposal already suggested. Note
that the identical overstatement sits in
`framework/artifacts/repository.py:129-166`, which is more careful but still
reasons as though a stored hash were evidence of provenance.

### F-013 — `is_clean` decides whether the survivorship warning is printed, and no test in the suite references it — **Medium**

**Claim.** One predicate decides whether every artifact derived from a source
carries the survivorship direction warning or omits it. It has zero test
references, and inverting its logic passes all 626 tests.

**Evidence.** `framework/data/survivorship.py:129-140` defines `is_clean` as
`all(getattr(self, name) is Retention.RETAINED for name in _HALF_LABELS)`.
`framework/data/survivorship.py:159-162` is the consumer: if `is_clean`, the
caveat is returned *without* `SURVIVORSHIP_DIRECTION` — the "INFLATES every return
measure and DEFLATES drawdown and tail measures SIMULTANEOUSLY" text that appears
in the one committed artifact at `artifacts/RPT-0001/1.0.0.yaml:62-66`.

`grep -rn "is_clean" tests/ framework/` returns two hits, both inside
`framework/data/survivorship.py` itself. Not one test calls it or asserts on it.

Mutation probe, run against a `git archive` copy in a scratch directory:

```
SURVIVED  survivorship: is_clean all() -> any()      626 passed, 1 skipped, 5 xfailed
KILLED    survivorship: UNKNOWN counts as clean      1 failed, 373 passed
```

The second mutant dies because the UNKNOWN case is covered indirectly through
`known_limitations()`. The first survives because no test uses a *mixed*
disclosure. Under `any()`, a source declaring `delisted_prices=RETAINED,
delisted_universe_membership=UNKNOWN` reports itself clean and its artifacts
silently lose the direction warning.

**Breach.** `constitution/Evidence_Standards.md:45`. The conclusion "a
survivor-only source cannot present itself as clean" is asserted at
`framework/data/contract.py:188-190` and defended by two dedicated test files
totalling 433 lines; the predicate that decides whether the caveat is actually
printed carries no evidence at all.

**Not rated High, and the boundary is worth stating.** No artifact today carries
a wrong caveat: `is_clean` is correct as written, and both existing sources
(`framework/data/dolthub.py`, `framework/data/ibkr.py:78-83`) answer in a shape
where `all()` and `any()` agree. The defect is that nothing would notice if that
changed.

**Failure.** *Prediction, and the roadmap already names the arrival.*
`docs/ROADMAP.md:214-219` records the owner's ruling that the contract must carry
both survivorship questions "even though the first implementation answers 'no' to
both … a contract that cannot express 'this source does not know past universe
membership' cannot record the answer on the day a better source does." The mixed
shape — `RETAINED` prices, `UNKNOWN` membership — is precisely the *expected next
source*, and it is the exact shape this predicate is untested on.

**Proposal.** Four assertions on the truth table, in
`tests/data/test_survivorship.py`: `(RETAINED, RETAINED)` clean;
`(RETAINED, UNKNOWN)`, `(UNKNOWN, RETAINED)` and `(RETAINED, SURVIVORS_ONLY)` not
clean, and each of the last three carrying `SURVIVORSHIP_DIRECTION` in
`known_limitations()`. Parametrised, that is roughly eight lines and it kills the
mutant.

### F-014 — The significance test's two-sidedness is asserted in a comment and by nothing else — **Low**

**Claim.** Every return series in the significance suite has a positive mean
against a zero null, so the property that a *losing* strategy is measurable is
untested. Removing the `abs()` that provides it passes all 626 tests.

**Evidence.** `framework/metrics/statistics.py:219-221` — "Absolute, because the
test is two-sided: an effect below the null becomes significant in the other
direction and needs the same sample to show it. `effect = abs(_mean(returns) -
null_return) / dispersion`". The two fixtures the module's tests use are
`tests/metrics/test_significance.py:42` `WEAK = (0.01, -0.02, 0.03, 0.00, 0.02)`
(mean +0.008) and `:48` `STRONG` (all eight values positive). Every call to
`significance()` and `minimum_observations_for_significance()` in that file passes
`null_return=0.0`. Mutation probe against the scratch copy:

```
SURVIVED  statistics: minimum-observations effect loses its abs() (one-sided)
          626 passed, 1 skipped, 5 xfailed
```

Under that mutant `clears(n)` is never true for a below-null mean, so
`significance()` raises "would need more than 1000000 observations" for every
series that loses money. Verified on the unmutated code that the honest answer
exists: a series of eight negative returns gives `t = -13.23, p = 3.3e-06,
significant = True, minimum_observations = 3`.

**Breach.** None in the constitution, so Low by the severity rule rather than by
judgement. The closest is ADR-012 rule 8's distinction between "not significant"
and "not enough data to tell" (`docs/DECISIONS.md:2102`), which the mutant
collapses in the direction that flatters — an underperforming strategy reads as
unmeasurable rather than as demonstrably bad.

**Failure.** *Prediction.* Someone refactors `minimum_observations_for_significance`
— it is the most intricate function in the module — and drops or misplaces the
`abs()`. The suite stays green. The first strategy Belay measures that is actually
losing money produces a `ValueError` about needing a million observations, or, if
a caller catches it, a "sample inadequate" verdict on a result that was perfectly
conclusive.

**Proposal.** One test: a below-null series through `significance()`, asserting
`t_statistic < 0`, `significant is True`, and `minimum_observations` equal to the
value for its mirror-image positive series. Four lines in
`tests/metrics/test_significance.py`.
