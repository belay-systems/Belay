## Findings

### F-019 — Eight guards on the capital and provenance path are asserted by nothing; a one-token change to each passes all 632 tests — **High**

**Claim.** Forty-nine plausible one-token bugs were applied to load-bearing logic
and the suite run against each. Thirty-six turned it red. Thirteen did not, and
after removing four that are masked by a redundant guard elsewhere and two whose
consequence is a floating-point boundary, **eight remain where the mutation is
both undetected and consequential**. Four of the eight mint a signed, valid,
storable artifact stating something untrue about a strategy's capital.

**Evidence.** Baseline verified green before and after (`632 passed, 1 skipped, 5
xfailed`). Each row is one mutation, applied alone, with `__pycache__` cleared:

| Guard | Mutation | Result with the mutation applied |
|---|---|---|
| `framework/artifacts/validator.py:157` | `if False and artifact.type is ArtifactType.STRATEGY and artifact.strategy_stage is None:` | a STRATEGY artifact with `strategy_stage: None` validates True |
| `framework/artifacts/validator.py:165` | same, on the converse check | a REPORT carrying `strategy_stage=PRODUCTION` validates True |
| `framework/artifacts/review.py:228` | `if False and resulting_stage is not StrategyLifecycle.RETIRED:` | `review_artifact(... outcome=RETIRE ...)` returns a signed record reading `Retire : Promotion Review -> Micro Capital` |
| `framework/artifacts/review.py:265` | `and not climbed` → `and climbed and False` | a signed record reading `Promote : Production -> Paper Trading` |
| `framework/data/fetch_record.py:138` | `if False and on_disk != digest:` | a record signed over one fetch's bytes may name a real file holding different data |
| `framework/data/fetch_record.py:317` | match on the hash alone rather than `(path, hash)` | the exact regression `framework/data/fetch_record.py:305-311` records as already having happened once |
| `framework/data/fetch_record.py:367` | delete the pre-write `_survivorship_of(source)` call | rule 9's "checked **before** anything is written" (`framework/data/fetch_record.py:359-362`) is unheld |
| `framework/data/survivorship.py:138` | `all(` → `any(` | a source that is `RETAINED` on prices and `SURVIVORS_ONLY` on universe membership reports `is_clean` and every artifact derived from it loses the `SURVIVORSHIP_DIRECTION` caveat |

The last row is F-016, already open, and the mutation shows why no test caught it:
`grep -rn is_clean tests/` returns nothing, and every disclosure any test builds
sets both halves to the same value (`tests/data/test_survivorship.py:50-51`,
`:80-81`, `:110`, `:122-123`; `tests/data/test_survivorship_cannot_be_softened.py:51-52`).
The mixed case is the only one where `all` and `any` differ and no test constructs
it.

Two further mutations survived and are recorded as boundary gaps rather than
counted above: `framework/metrics/statistics.py:301` `observed_p < alpha` → `<=`,
and `:303` `len(returns) >= needed` → `>`.

Four survivors were excluded because a second guard still refuses:
`framework/artifacts/integrity.py:84` and `framework/artifacts/repository.py:204`
are each shadowed by an earlier `integrity_hash is None` check
(`framework/artifacts/validator.py:259`, `framework/artifacts/repository.py:179`),
and both were confirmed to still raise with the mutation applied. That redundancy
is a design strength and is reported as one.

**Breach.** `constitution/Evidence_Standards.md:45` — "Every conclusion must
reference supporting evidence." The conclusion "these eight guards hold" is
supported by reading the code, which is the same standard Belay refuses from a
strategy. `.github/workflows/conformance.yml:15-17` states the entitled claim
correctly — "a green badge here means the suite ran" — and this finding is the
size of the gap between that and health.

**Failure.** *Fact for the mechanism, prediction for the consequence.* Stage 3
gives `review.py` its first real caller. A session refactoring
`_check_outcome_matches_movement` — the function whose own docstring at
`framework/artifacts/review.py:217` says "The order of these branches is
load-bearing" — reorders or narrows one branch. The suite stays green, the change
lands, and the first REVIEW artifact Belay ever signs records a retirement that
funds the strategy. `ArtifactRepository` is append-only, so the record cannot
afterwards be corrected; `Knowledge/Versioning.md:25` — "No version is
overwritten."

**Proposal.** Eight regression tests, one per row, each confirmed red against the
mutation before it is written green. They are cheap: every one is a two-line
construction and an assertion, and six of the eight need no fixture at all. Add
the two boundary cases as a ninth and tenth if they are wanted; they are not
required by this finding. No production code changes.

**Claim.** Nine tracked locations cite

"Remain Current Stage". The nine citations:

- `framework/artifacts/review.py:129` — the comment above the check

  both Accepted
- `strategies/ReviewTemplate.md:75`
- `docs/HANDOFF.md:1307`
- `tests/artifacts/test_review_decision.py:127`

The line moved and the citations did not. `git show 9ad15be:workflows/Monthly/StrategyPromotion.md`
carries the sentence at line 37; `git show d2ac655:...` — the commit that applied
ADR-006's reconciliation and added three criteria — carries it at line 43.

**Neither existing enforcement can see it.**
`tests/test_session_handoff.py:178` checks only that the cited line number is

the cited line, and so that an ambiguous basename with more than one candidate is
reported rather than passed on the longest. That second half is the general fix
and is what would have caught this; the renumbering alone leaves the mechanism
that produced it intact.

### F-023 — `scripts/status.py`'s "could not run" branch destroys the dashboard instead of reporting, so the one case it was written for produces nothing at all — **Medium**

**Claim.** `run_tests()` has a branch for the case where pytest cannot be launched.
It returns a dict missing the `watched` key, which `render()` reads
unconditionally, so `status.py` raises `KeyError` and writes no page. The
docstring says the opposite.

**Evidence.** `scripts/status.py:84` — the exception branch returns
`{"ok", "passed", "failed", "note"}` and no `"watched"`. `scripts/status.py:306` —
`{tests["watched"]}`, unguarded. Executed against a copy with `subprocess.run`
raising `OSError`:

```
status.main() raised: KeyError 'watched'
  File "scripts/status.py", line 385, in main
    OUTPUT.write_text(render(data), encoding="utf-8")
  File "scripts/status.py", line 306, in render
```

`scripts/status.py:70-74` states the intent this contradicts: pytest is run "as a
separate process rather than importing it, so a test that crashes cannot take this
script down with it."

Two further defects in the same branch, both already covered by the open F-009 and
recorded here only because they were re-derived in the same probe: with pytest
absent rather than unlaunchable, `run_tests()` returns
`{'ok': False, 'passed': 0, 'failed': 0, 'watched': 0, 'note': 'suite is not green'}`
— a note that is false, since nothing ran — and `scripts/status.py:394` prints
`0 passing, 0 failing`.

**Breach.** `constitution/Operational_Constraints.md:5` — "Belay shall maintain
accurate records." Medium rather than higher because the failure is loud: the
`dashboard builds` job at `.github/workflows/conformance.yml:100-113` would go red.
The defect is that the branch written to keep the dashboard reporting under
exactly this condition is the branch that stops it.

**Failure.** *Prediction.* A session on a machine where the interpreter path is
wrong, or a runner under memory pressure, runs `scripts/status.py` and gets a
traceback instead of a page that says "the suite could not be run". The page it
would have got is the one artefact designed to distinguish "not measured" from
"measured and fine", which is `scripts/status.py:18-20`'s whole stated purpose.

**Proposal.** Add `"watched": 0` to the dict at `scripts/status.py:84`, render
`note` on the card when it is non-empty, and set the note to "could not run" on
the pytest-absent path as well as the exception path. Three lines. The F-009 fix
already ruled by the owner (`docs/OwnerDecisions.md:954`) should absorb this
rather than land separately.

### F-024 — Nothing checks an artifact's identifier prefix against its type, and identifiers are permanent — **Medium**

**Claim.** `Knowledge/Identifiers.md` maps each prefix to a kind of artifact.
No code compares the two. A promotion decision record can be created, validated
and stored permanently under `STRAT-`, and a strategy under `REV-`.

**Evidence.** `framework/artifacts/factory.py:34` calls
`validate_identifier(identifier)`; `framework/identifiers.py:108-115` takes only
the string and checks its shape and prefix against a whitelist, never against the
artifact's type. Executed against the repository as committed:

```
a STRATEGY artifact filed under the REVIEW prefix
  type / id : Strategy / REV-0001   validates: True   stored at REV-0001/1.0.0.yaml

a REVIEW decision record filed under the STRATEGY prefix
  type / id : Review / STRAT-0009   validates: True   stored at STRAT-0009/1.0.0.yaml
  reads back as: Promote -> Micro Capital
```

**Breach.** `Knowledge/Identifiers.md:25-57` maps `STRAT` to Strategy and `REV` to
Review; `Knowledge/Identifiers.md:61` — "Identifiers never change." Medium: this
is drift between a governing document and the code that has not yet produced a
false claim, because `artifacts/RPT-0001/1.0.0.yaml` is the only artifact that
exists and its prefix is right.

**This is not the open finding it resembles.** `docs/HANDOFF.md:2394`,
"ArtifactType And The Identifier Prefixes Are Two Vocabularies That Disagree", is
about the two lists not containing the same kinds — `PORTFOLIO` and `FAILURE` have
no prefix, `DOC` has no member. That finding closing would not close this one:
even with the vocabularies reconciled, nothing would compare an individual
artifact's prefix to its own type.

**Failure.** *Prediction.* The first REVIEW record Belay signs is created by a
caller that copies an identifier from a nearby example. It stores under the wrong
directory, `ArtifactRepository` accepts it, and
`Knowledge/Identifiers.md:61` makes it uncorrectable. Any later walk that selects
strategies by prefix — the obvious shape for a promotion pipeline that does not
exist yet — silently omits it or silently includes a review among the strategies.

**Proposal.** A mapping from `ArtifactType` to prefix beside
`DELIVERABLE_ARTIFACT_TYPE` in `framework/artifacts/enums.py`, checked in
`ArtifactFactory.create` after `validate_identifier`, covering the seven types
that have a prefix and skipping `PORTFOLIO` and `FAILURE` until the open
vocabulary finding is ruled. One test per covered type. It touches no governance
document, because it enforces a mapping `Knowledge/Identifiers.md:25-57` already
states.
