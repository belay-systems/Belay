### F-007 — A strategy can still be signed into existence at PRODUCTION; F-001's fix guards the factory, not the artifact — **Critical**

**Claim.** F-001 was closed by refusing a non-`IDEA` birth stage inside
`ArtifactFactory.create()`. `Artifact(...)` and `ArtifactIntegrity.sign()` are both
public and neither is guarded, so the same artifact — signed, valid, persistable —
is still constructible in two lines.

**Evidence.** `framework/artifacts/factory.py:61-71` is the guard, and it is on
that method only. `framework/artifacts/integrity.py:71` — `sign()` is a public
classmethod that computes and attaches the hash for any artifact handed to it.
`framework/artifacts/validator.py:145-168` — `_validate_lifecycle` checks that
`strategy_stage` is a `StrategyLifecycle`, that STRATEGY artifacts have one and
that others do not. It still never looks at *which*. Run against the repository as
committed:

```
ArtifactFactory().create(..., strategy_stage=StrategyLifecycle.PRODUCTION)
→ refused: ValueError  a strategy cannot be created at stage ...

Artifact(id="STRAT-0002", title="Born at production",
         type=ArtifactType.STRATEGY,
         strategy_stage=StrategyLifecycle.PRODUCTION)
signed = ArtifactIntegrity.sign(art)
→ signed.strategy_stage       -> StrategyLifecycle.PRODUCTION
  integrity verify            -> True
  ArtifactValidator().validate -> True
  ArtifactRepository.save      -> /tmp/.../STRAT-0002/1.0.0.yaml
  repo.get("STRAT-0002").strategy_stage -> StrategyLifecycle.PRODUCTION
  loaded integrity ok          -> True
```

`framework/artifacts/factory.py:55-60` states the defence that is supposed to cover
this: "`ArtifactSerializer.load()` builds `Artifact(...)` directly, and the
repository verifies the integrity hash on read, so a stage that was earned survives
the round trip while a hand-edited one does not." **The first half of that is true
and the second half is the gap.** Executed, both directions:

```
save an IDEA strategy, hand-edit `strategy_stage: Idea` -> `Production` in the YAML
repo.get("STRAT-0003") → refused: ValueError  integrity hash does not match ...
hand-edit `observations: 28` -> `2800` in artifacts/RPT-0001/1.0.0.yaml
repo.get("RPT-0001")   → refused: ValueError  integrity hash does not match ...
```

The read-time check defends against *tampering*. It cannot defend against
*construction*, because the constructor's output is signed by the same public
function the repository then verifies against. Nobody has to hand-edit.

The asymmetry inside the validator is the proof that the pattern was available and
was not applied here. `framework/artifacts/validator.py:227-232` re-derives
`evidence_level` and refuses a mismatch, and its comment gives the reason
verbatim: "Without this an artifact built by calling `Artifact()` directly could
claim Level A while carrying nothing but hypotheses, and that claim is what a
promotion gate reads." `strategy_stage` is the same kind of claim, read by the same
kind of gate, and gets no such check.

**Breach.** `constitution/Paper_First_Capital_Doctrine.md:5-7` — "Every strategy
begins with zero capital. No exceptions."
`constitution/Immutable_Laws.md:23-25` (Law III, capital must be earned) and
`constitution/Immutable_Laws.md:39` (Law V, no department may bypass validation).

**Failure.** Identical to F-001's, and the reasoning there stands unchanged: a
Stage 5 service, an import script or a fixture builds a STRATEGY artifact from a
config that carries a stage field. It is signed, it validates, it persists, and it
reloads with its integrity intact — the audit trail that would expose it is the
sequence of REVIEW artifacts, and there are none to be missing because no review
ever happened. What is new is that a reader now has *positive* evidence the hole is
closed: F-001 is in the closed table at `docs/HANDOFF.md:1921-1965`, ten tests were
written against it (`tests/artifacts/test_factory.py::test_a_strategy_cannot_be_born_past_idea`
parametrized over all eight non-`IDEA` stages), and every one of them passes. A
closed finding with a green parametrized suite behind it is harder to re-open than
an open one.

**Proposal.** Move the check to where the claim is read rather than where it is
issued: add a `_validate_birth_stage` to `ArtifactValidator` in the shape of
`_validate_evidence` at `framework/artifacts/validator.py:221-238` — a STRATEGY
artifact at version `1.0.0` with no `parent_hash` may only stand at `IDEA`. That
covers every construction path, sanctioned or not, and leaves later stages
reachable only through a version chain. Keep the factory guard; it is the earlier
and clearer error message. `docs/HANDOFF.md:1921-1965` should be corrected to say
what F-001's fix does and does not cover, because a closed table entry is the
thing a future session will read instead of the code.

### F-008 — The survivorship guard is defeated three ways in committed code, and all three are recorded outside the finding register — **High**

**Claim.** The two-link guarantee that "a survivor-only source cannot present
itself as clean" is bypassable by a four-line subclass, by one attribute
assignment, and by a `SimpleNamespace`. All three were raised with executed
evidence on 2026-08-02, none has been fixed, and none appears in the finding
register that `scripts/status.py` counts.

**Evidence.** Run against the repository as committed, `main` at `dbfd07f`:

```
class Softened(SurvivorshipDisclosure):
    def known_limitations(self): return "None."
disclosure_from(Src(survivorship=Softened(SURVIVORS_ONLY, SURVIVORS_ONLY, "queried")), ...)
→ known_limitations -> 'None.'

s = Src(survivorship=<survivor-only>)
s.survivorship = clean        → AttributeError: property has no setter
s._survivorship = clean       → accepted
disclosure_from(s, ...)       → 'Survivorship established as — delisted prices:
                                 Retained, ... Basis: trust me'   (no INFLATES clause)

duck = SimpleNamespace(name=<real DoltHub name>, survivorship=<clean>)
isinstance(duck, MarketDataSource) → False
disclosure_from(duck, ...)         → accepted, carries the real source's name
```

Each corresponds to a specific claim in the code:

- `framework/data/survivorship.py:142-152` — `known_limitations()` "takes no
  arguments, and that is the mechanism of ADR-012 rule 7 rather than an oversight:
  there is no override parameter because a caller who could pass one could suppress
  the caveat." There is no override *parameter*; there is an override *method*, and
  both guards test `isinstance(..., SurvivorshipDisclosure)`, which admits
  subclasses (`framework/data/contract.py:209`, `framework/data/fetch_record.py:436`).
- `framework/data/contract.py:221-227` — `survivorship` is "Read-only after
  construction". It is read-only under its public name only; `_survivorship` is a
  plain instance attribute on a non-frozen, non-slotted class
  (`framework/data/contract.py:218`). `tests/data/test_survivorship_cannot_be_softened.py:211-218`
  is named `test_the_disclosure_cannot_be_reassigned_after_construction` and
  asserts only the public half — one underscore narrower than its own name.
- `framework/data/fetch_record.py:435` — `_survivorship_of` reads
  `getattr(source, "survivorship", None)` and type-checks the *disclosure*, never
  the *source*. Its docstring at `:426-434` describes link two as catching "a
  subclass that overrides `__init__` without calling `super().__init__`"; a
  non-subclass never meets link one at all.

**This is live on the only production data path Belay has.** `_survivorship_of` is
called at `framework/data/fetch_record.py:96`, inside `fetch_record()`, which
`fetch_and_record` calls and which `scripts/adopt_aapl.py:65` and
`scripts/verify_clone.py:86` reach. That path produced
`artifacts/RPT-0001/1.0.0.yaml`, the only artifact this repository has ever kept,
and its `known_limitations` field is exactly what these three routes rewrite.

**And they are registered nowhere.** `docs/HANDOFF.md:2281-2303` is the finding
table; `scripts/status.py:187-213` counts its sections and the dashboard reports 21
open findings. None of the 21 rows is any of these three. Their only record is
`reports/review/2026-08-02-f003-partial-pass.md:43-121` and one narrative paragraph
at `docs/HANDOFF.md:3324-3328` — neither of which the dashboard counts, and the
paragraph sits under a "READ FIRST" heading about a change that has since moved to
a branch.

**Breach.** `constitution/Evidence_Standards.md:45` — "Every conclusion must
reference supporting evidence." A signed fetch record whose survivorship clause
reads "None." is a conclusion with its most distorting caveat removed. And
`constitution/Governance.md:27` — "Institutional memory is mandatory" — for the
register: three executed defects held only in a report file are not in the memory
the project reads.

**Failure.** *Fact for the mechanism, prediction for the consequence.* A second
data source is added — the obvious next one is the IBKR adapter at
`framework/data/ibkr.py:102`, which already exists. Whoever writes it subclasses
`SurvivorshipDisclosure` to phrase the caveat in the vendor's own words, or wires a
test double that is not a `MarketDataSource`, and the resulting fetch records carry
a survivorship clause that the source did not establish. Every metric derived from
that data inherits it. Nothing turns red: `tests/data/test_survivorship_cannot_be_softened.py`
passes on all three routes today. The register that would have told the author the
holes were known does not contain them.

**Proposal.** Three one-line changes and one register entry, none of which needs a
ruling. (1) `@final` on `SurvivorshipDisclosure.known_limitations`, or compare
`type(x) is SurvivorshipDisclosure` at both guards. (2) `__slots__` on
`MarketDataSource`, or store the disclosure under a name-mangled attribute, so
`_survivorship` is not assignable. (3) `isinstance(source, MarketDataSource)` at the
head of `_survivorship_of`. (4) Add the three to `docs/HANDOFF.md`'s Open Findings
table as one row with a section, so `scripts/status.py` counts them — until then
the dashboard under-reports by three, which is the same defect
`docs/HANDOFF.md:2141-2156` was written to fix for F-001..F-006.

### F-009 — A suite that could not run is reported as "0 passing, 0 failing", and the field that says otherwise is computed and discarded — **Medium**

**Claim.** `run_tests()` builds a `note` distinguishing "the suite failed" from
"the suite could not be run". Nothing renders it. A suite that never executed is
reported in the same words as a suite with zero failures — and on the one code path
that handles "could not run" literally, the dashboard crashes instead.

**Evidence.** Two mechanisms, both executed.

*One — the note is discarded.* `scripts/status.py:84` returns
`{"note": f"could not run: {exc}"}` and `scripts/status.py:98` returns
`{"note": "suite is not green"}`. Neither is read anywhere: `grep -n "note"
scripts/status.py` returns those two writes plus a CSS class at `:258` and the
untested-modules warning at `:316`, which is a different string. The terminal line
at `scripts/status.py:394` prints only `passed` and `failed`, and
`scripts/status.py:295` renders `f"{tests['failed']} failing"` whenever `ok` is
false. Both are zero when nothing ran. **This happened in this review**, on the
first command executed against a fresh checkout:

```
$ python scripts/status.py
Belay status - 2026-08-14 06:27 UTC
  tests               0 passing, 0 failing
  gaps watched        0 (xfail conformance checks)
```

The suite had not run at all — `pytest` is in the `dev` extra
(`pyproject.toml:26`) and was not installed. "0 failing" is the text of a healthy
suite.

*Two — the "could not run" branch crashes the renderer.* `scripts/status.py:84`
omits the `watched` key that `scripts/status.py:306` reads unconditionally.
Executed, by making `subprocess.run` raise `TimeoutExpired`:

```
run_tests() -> {'ok': False, 'passed': 0, 'failed': 0, 'note': "could not run: ... timed out after 300 seconds"}
'watched' present? False
render RAISED -> KeyError 'watched'
```

So the branch written to handle a suite that cannot run produces no dashboard at
all. `refresh-status.cmd:20-31` then reports the wrong cause: "Could not build the
dashboard. Most likely cause: Python is not on your PATH."

**Breach.** `constitution/Evidence_Standards.md:45` — "Every conclusion must
reference supporting evidence." "0 failing" is a health conclusion resting on no
run. `constitution/Operational_Constraints.md:19` — "Belay shall communicate
uncertainty explicitly."

**Rated Medium rather than High, and the reason is a real mitigation.** The HTML
pill is red (`p-bad`, `scripts/status.py:294`) and `refresh-status.cmd:35-43`
pauses with a warning on the non-zero exit code. The owner is told *something* is
wrong. They are told the wrong thing — "the test suite is NOT passing" when the
truth is that nothing was measured — and the `note` that carries the difference is
computed and thrown away. This is the failure mode `scripts/status.py:7-11` says the
script exists to prevent, inside the script itself.

**Failure.** *Fact — it already occurred, above.* A session or a cloud run starts
from a clone, runs the entry point `docs/HANDOFF.md:3262-3264` names as more
reliable than HANDOFF itself, and reads `0 passing, 0 failing`. On Windows the
`.cmd` pause says the suite is failing, which sends the reader looking for a broken
test that does not exist; on any other platform, or from the terminal directly,
there is no signal at all. Either way the dashboard's other twelve sections — which
did compute correctly — lend the zero their credibility.

**Proposal.** Print `tests["note"]` in `main()` whenever it is non-empty, and
render it in the test card; make `test_txt` read `"could not run"` rather than
`"0 failing"` when `passed + failed == 0 and not ok`. Add `"watched": 0` to the
dict at `scripts/status.py:84`. Three lines. A test that stubs `subprocess.run` to
raise and asserts `render()` returns a string would have caught the second half.
