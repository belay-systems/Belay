## Findings

### F-037 — The gate's SKIP decision is asserted by no test, and one file name on any branch stops every future review permanently, silently, and in the one shape the queued fix does not close — **High**

**Claim.** `scripts/review_due.py` decides whether this review runs. Its SKIP
branch can be deleted outright with the suite fully green. A report file dated
in the future — on any branch, merged or not — makes the gate print a SKIP line
with a negative age and exit 1, which the scheduled procedure must obey and
report as the whole of its output. A report file whose date is impossible
crashes the gate at exit 1, the same code as SKIP, against the contract the
module's own docstring states.

**Evidence.** Three probes, each a single file on a hand-written
`refs/remotes/origin/*` ref in a scratch clone, and one mutation.

1. **The branch is asserted by nothing.** `scripts/review_due.py:204` —
   `if age < MINIMUM_AGE_DAYS:`. Replaced with `if False:`, so the gate can
   never skip and authorises a run every firing → **`704 passed, 1 skipped,
   5 xfailed`**. That is the duplicate-review failure the file was written to
   prevent, and nothing goes red. For contrast, changing the *value*
   (`:40`, `MINIMUM_AGE_DAYS = 12` → `99999`) fails 23 tests: every fixture in
   `tests/test_review_due.py` is dated far in the past, so the threshold's value
   is asserted incidentally while the branch that uses it is not asserted at all.
   `grep -n "DUE\|SKIP" tests/test_review_due.py` finds `DUE` asserted at `:176`
   and `:194` and **no test that produces a SKIP verdict**, in a file whose own
   comment at `:225` reads "0 is DUE and 1 is SKIP; this is neither".

2. **A date-shaped substring is enough, today.** `scripts/review_due.py:42`
   compiles `REPORT` without anchors and `:121` calls `REPORT.search(path)`. One
   file, `reports/review/draft-2099-01-01-review.md`:

   ```
   SKIP — last review was -26382 days ago (draft-2099-01-01-review.md, on probe-one). Next due 2099-01-13.
   ```

   exit 1.

3. **And the queued fix does not close it.** `docs/NOW.md`'s third task names
   "`fullmatch` on report names" as a known gate item. A `fullmatch` rejects
   probe 2 and not this one — `reports/review/2027-01-01-review.md`, a correctly
   named report dated in the future:

   ```
   SKIP — last review was -84 days ago (2027-01-01-review.md, on probe-two). Next due 2027-01-13.
   ```

   exit 1. Nothing in `newest_report()` (`:111-129`) or `verdict()` (`:183-214`)
   rejects a date after today, and `:202`'s `age = (today - when).days` is
   printed as a verdict whatever its sign.

4. **The undesigned stop takes SKIP's exit code.**
   `reports/review/2026-13-45-review.md` → `date.fromisoformat` at `:122` raises
   an uncaught `ValueError: month must be in 1..12`; stdout is **empty** and the
   exit code is **1**. The designed stop, for comparison, behaves as documented:
   an `F-[999]` in any counted prose (written in brackets here because
   `highest_finding()` at `scripts/review_due.py:155-161` counts every ASCII
   `F-NNN` in this file too, and the bare form would stop the gate for good)
   raises `GateCannotAnswer` and exits **2** with
   its reason on stderr. `scripts/review_due.py:25-27` states the contract — "the
   gate stops: exit 2, a reason on stderr, nothing on stdout" — and `:175-180`
   implements it only for the exception the gate raises itself.

**Breach.** `constitution/Evidence_Standards.md:45` — "Every conclusion must
reference supporting evidence." The conclusion "the cadence holds" rests on
reading `verdict()`, which is the standard Belay refuses from a strategy; this is
the grading F-032 received for the same shape. Additionally
`constitution/Operational_Constraints.md:5` — "Belay shall maintain accurate
records" — for a verdict that states a review happened 84 days from now.

**Failure.** *Fact for every probe, prediction for the cost.* The scheduled
prompt's Step 1 and `.claude/skills/belay-review/SKILL.md` both forbid this
reviewer from reimplementing the check or listing `reports/review/` by hand, and
for good reason — the hand-listing is the bug the gate replaced. So a SKIP line
is final. A session that mis-dates a report, or names a draft
`draft-<date>-review.md`, or types `2026-13-45`, ends the adversarial review of
this repository with no error anyone will see: the routine fires weekly, prints
one line, and stops. `reports/review/` is the only place findings are written,
so the series simply stops growing while the suite stays green and the dashboard
keeps reporting health.

**Proposal.** Three changes in one file and two tests. In `newest_report()`,
anchor the pattern (`fullmatch` against the basename) and raise
`GateCannotAnswer` rather than `ValueError` when `date.fromisoformat` rejects the
text — which also fixes probe 4's exit code. In `verdict()`, raise
`GateCannotAnswer` when `when > today`, naming the file and the branch: a report
dated in the future is a defect to report, never a cadence to obey. In
`tests/test_review_due.py`, one test that a recent report yields SKIP on exit 1
— which is what makes the branch exist — and one that a future-dated report stops
the gate rather than skipping.

### F-038 — The gate discards the result of the `git fetch` it performs, so an unreachable remote yields a confident `DUE` and a finding number computed from stale refs — **High**

**Claim.** `scripts/review_due.py` fetches before reading refs, and ignores
whether the fetch worked. When it fails, the gate answers from whatever the local
clone already had, prints `DUE` and a first finding number with exit 0, and says
nothing on stdout about the fact that it is blind to every branch pushed since
the last successful fetch. That is the 2026-08-21 collision with a different
cause.

**Evidence.**
- `scripts/review_due.py:190` — `subprocess.run(["git", "fetch", "--quiet",
  "--all"], check=False)`. It bypasses the module's own `git()` helper, whose
  docstring at `:71-73` says "**A failed command raises for the same reason**:
  `""` is what an empty file looks like", and whose `may_fail` escape is
  documented as "for `rev-parse` alone".
- The two lines directly above it, `:188-189`, state why the fetch is there:
  "Refs are only as current as the last fetch, and a stale ref is exactly the
  blindness this script exists to remove."
- Constructed. In a scratch clone with `git remote set-url origin
  /nonexistent/path/to/nowhere.git`, `git fetch --quiet --all` exits **128**
  ("Could not read from remote repository"), and the gate then prints:

  ```
  DUE — last review was 14 days ago (2026-09-25-review.md, on main).
    first finding: F-037
  ```

  exit **0**. git's own `fatal:` lines reach stderr; the verdict on stdout
  carries no qualification of any kind.
- No test covers it: the fourteen tests in `tests/test_review_due.py` are listed
  in F-037 above, and none concerns the fetch.

**Breach.** `constitution/Evidence_Standards.md:45`. The gate's conclusion is
"these are all the refs that exist", and the one command that establishes it may
have failed. Additionally `constitution/Governance.md:27` — "Institutional memory
is mandatory" — for the consequence: a finding number issued twice stops the
F-series naming one finding each, which `docs/FINDINGS.md:9-11` makes the way a
finding is cited at all.

**Failure.** *Fact for the construction, prediction for the cost.* The scheduled
run is unattended; nobody reads its stderr. Any network interruption, expired
credential, or proxy refusal at the moment of the firing turns the gate from "the
only authority on the next number" into a reader of a stale clone. It then issues
a number a branch pushed since the last fetch has already taken, and the next
review inherits two findings with one name — exactly the failure the module
docstring at `:11-16` records, where the gate "could not see" a branch and "reused
seven finding numbers that were already claimed and already ruled on. Four of its
nine findings were rediscovery." The fix there was to read all refs. Reading all
the refs you happen to have is the same defect at one remove.

**Proposal.** Route the fetch through `git()` so a non-zero exit raises
`GateCannotAnswer`, or keep `subprocess.run` and raise on `returncode != 0` with
git's stderr in the message. Either way the gate stops rather than answers, which
is what `:25-27` already promises for every other unreadable input. One test: a
clone whose `origin` does not resolve produces exit 2 and no number.

### F-039 — The two guards holding ADR-012's significance conventions are asserted by nothing; removing one mints a signed, validating Level C report that calls a p-value of 0.56 statistically significant — **High**

**Claim.** `significance()` validates its `alpha` and its `periods_per_year`.
Both checks can be removed one at a time with the suite fully green, and no test
anywhere in the repository ever passes an out-of-range value for either. With the

sits on a p-value of 0.5614.

**Evidence.** A sweep of every `if <cond>:` immediately followed by a `raise`
under `framework/data/` and `framework/metrics/` — 53 guards — each disabled
alone on a scratch clone with `__pycache__` cleared and `python -m pytest -q`
run. Fifteen survived. Eight were then triaged by calling the function the guard
protects:

| guard | removed → | verdict |
|---|---|---|
| `framework/metrics/statistics.py:274` (`alpha` in `significance`) | `significant: True`, p 0.5614 | **wrong answer** |
| `framework/metrics/statistics.py:272` (`periods_per_year` in `significance`) | `significant: True` against a negated null | **wrong answer** |
| `framework/metrics/statistics.py:210` (`alpha` in `minimum_observations_…`) | `ValueError` from `framework/metrics/distributions.py:161` | masked |
| `framework/metrics/statistics.py:176` (`confidence` in `confidence_interval`) | same, `distributions.py:161` | masked |
| `framework/metrics/risk_adjusted.py:58`, `framework/metrics/volatility.py:76` | `math domain error` from `sqrt` | masked |
| `framework/metrics/risk_adjusted.py:53`, `framework/metrics/statistics.py:103` | the dispersion guard's own `ValueError` | masked |

- **The two that are real, constructed and run against `main` at `61afc3f`.**
  With `framework/metrics/statistics.py:274` disabled, `704 passed, 1 skipped,
  5 xfailed`, and:

  ```
  validates: True
  evidence_level: EvidenceLevel.HISTORICAL
    observations: 30
    alpha: 1.0
    significant: True
    minimum_observations_for_significance: 1000000
  ```

  A signed `Validation Report` over thirty hand-made returns whose p-value is
  0.5614 — noise — asserting significance. (The 1,000,000 in the same artifact is
  open finding F-027, arriving unprompted.) With `:272` disabled instead, `704
  passed`, and `significance(..., null_return=0.10, periods_per_year=-252)`
  returns `significant: True`: `:278` computes `per_period_null = null_return /
  periods_per_year`, so an annual hurdle of **+10%** becomes a per-period null of
  **−0.0004**, and the series is tested against a negative benchmark.
- **Nothing exercises either bound.** `grep -rhoE
  "(alpha|confidence|periods_per_year)=[-0-9.A-Za-z_]+" tests/ --include='*.py' |
  sort | uniq -c` gives, for the whole suite: `alpha` is only ever `0.05` or
  `0.01`; `periods_per_year` only `PERIODS`, `252`, `1`, `2`; `confidence` only
  values inside `(0, 1)`. No out-of-range convention is ever passed. (`confidence=42.0`
  in that output is the `Artifact.confidence` field, a different check, and that
  one *is* tested.)
- **One further survivor of the same shape, recorded without a failure sentence.**
  `framework/data/store.py:88` is the guard that refuses a symbol reducing to no
  usable path segment. Removed → `704 passed`, and `_slug("..")` returns `".."`
  and `_slug("")` returns `""` where the unmutated code refuses both;
  `framework/data/store.py:76-77` states the stake — "a symbol that silently
  became a directory separator would write outside the store". `grep -n "_slug"
  tests/data/*.py` returns **nothing**: the guard has zero test references. It is
  listed here rather than as its own finding because no realistic path from a
  vendor response to a `..` symbol was constructed, so by this skill's own rule
  the failure sentence cannot be written.

**Breach.** `constitution/Evidence_Standards.md:45` — "Every conclusion must
reference supporting evidence." Same breach and same grade as F-032, for the same
reason: the conclusion "these conventions are enforced" rests on reading the
code. ADR-012 rule 3 is what requires `alpha` to be stated rather than defaulted
(`docs/DECISIONS.md:2102`), and a stated-but-unvalidated `alpha` satisfies the
letter of it.

**Failure.** *Fact for the construction, prediction for the cost.* No strategy and
no capital exist, so nothing has been decided on such an artifact. The cost
arrives at Stage 3, where the backtester's first job is to emit exactly these
artifacts. `constitution/Capital_Authority.md:11-14` makes `Statistical edge` one
of six inputs determining capital, and `significant` is the field that carries it.
The 2026-09-25 review's own "Not found" section recorded that these functions
"all take every convention as a required argument with no default" — true, and it
is the weaker of the two claims. Required and unvalidated is the state in which
the next edit to `significance()` can delete the bound and land green, and the
artifact that results is auditable only by a reader who notices `alpha: 1.0`
sitting in the content block.

**Proposal.** Two tests, roughly four lines each, in
`tests/metrics/test_significance.py`: `significance(..., alpha=1.0)` raises, and
`significance(..., periods_per_year=-252)` raises. Then, so the next sweep is not
hand-made: a parametrised case over the convention bounds in
`framework/metrics/`, which covers the six masked guards above in the same shape
and converts their accidental masking into an assertion.

refusal uses `match=`. It is checkable — a `pytest.raises(ValueError)` with no

### F-042 — The dashboard figure the conformance suite explicitly delegates to is produced by an em dash, and changing one to a hyphen silently drops a roadmap stage with the suite green — **Medium**
