### F-045 — The artifact root is relative to the process directory, not to the clone, so Belay's institutional memory reports empty from anywhere else and rule 7's orphan check answers "clean" having seen nothing — **High**

**Claim.** `ARTIFACT_ROOT` and `STORE_ROOT` are bare relative paths resolved
against the current working directory. Run anything that uses their defaults
from a directory other than the clone root and the repository's one stored
artifact becomes invisible, a save mints a second complete and self-consistent
append-only store elsewhere, and `orphan_versions` — the ADR-013 rule 7 check
whose whole purpose is to make stored bytes with no record visible — returns the
empty tuple, which is its clean answer.

**Evidence.**
- `framework/artifacts/repository.py:34` — `ARTIFACT_ROOT = Path("artifacts")`,
  and `framework/data/store.py:39` — `STORE_ROOT = Path("data") / "market"`.
  Both are module constants with the reason written beside them;
  `framework/artifacts/repository.py:22-24` gives it as "Relative, so the
  artifacts travel with a clone", citing `constitution/Governance.md:27`.
  **Relative to the clone and relative to the process directory are not the same
  thing, and the comment names the first while the code does the second.**
- Constructed. From an empty scratch directory with `PYTHONPATH` pointing at the
  repository:

  ```
  ARTIFACT_ROOT resolves to  <scratch>/artifacts
  STORE_ROOT    resolves to  <scratch>/data/market
  ArtifactRepository().identifiers()        -> []
  ArtifactRepository().versions('RPT-0001') -> []
  orphan_versions(SeriesStore(), repo)      -> ()
  ```

  Run from the clone root the same three calls return `['RPT-0001']`,
  `['1.0.0']` and `()`. The one record Belay holds is reported as absent, and
  the orphan check cannot tell "nothing is unaccounted for" from "I am standing
  in the wrong directory".
- `framework/artifacts/repository.py:52` — `if not self.root.is_dir(): return []`.
  An absent artifact root and an empty one produce identical output, with no
  diagnostic.
- `framework/data/fetch_record.py:313-318` — `orphan_versions` iterates
  `store.all_versions()`, which is empty when `STORE_ROOT` does not resolve to a
  directory, so the comprehension yields nothing. Its own docstring at `:306-311`
  records that an earlier version "reported a store clean while one of its two
  versions had no record naming it" and concludes "Both halves have to agree" —
  this failure empties both halves at once.
- It is not a hypothetical invocation. `scripts/adopt_aapl.py:53` constructs
  `SeriesStore()` and `ArtifactRepository()` on their defaults and prints the
  orphan count at `:62` and `:82`. The repository already knows the process
  directory matters and handles it in exactly one place:
  `refresh-status.cmd:12` is `cd /d "%~dp0"`, with the comment at `:9-10`
  explaining that it exists "so the script works no matter where it is launched
  from". `scripts/status.py:35` resolves its own root from `__file__`;
  `framework/config.py:3` does too. The artifact and series roots are the
  outliers.

**Breach.** `constitution/Governance.md:27` — "Institutional memory is
mandatory." A memory store whose location is whichever directory the operator
happened to be in is not mandatory memory; it is one store per working
directory. `framework/artifacts/repository.py:24` cites this same line as the
reason the path is relative.

**Failure.** *Fact for the construction; prediction for the cost.* Belay's
operating plan is a small always-on machine at home running daily workflows
(`docs/HANDOFF.md`, "A Home Machine Cannot Guarantee A Halt Within Seconds").
A scheduler is the normal way to run something daily and a scheduler's working
directory is whatever it was configured with, not the clone root. On the first
such run the fetch stores bytes under a fresh root, saves a record beside them,
and reports zero orphans — all true statements about a store nobody will ever
look in again, while the clone's own `artifacts/` directory silently stops
growing. Nothing goes red, because every individual record is sound; what is
wrong is the claim the directory makes about them. This is the same shape as
the registered finding "An Identifier Reused At A New Version Is Silently
Mis-Filed", one level up: there two unrelated fetches become two versions of one
artifact, here two unrelated stores both claim to be the institutional memory.

**Proposal.** Resolve both constants against the repository root rather than the
process directory — `Path(__file__).resolve().parents[2] / "artifacts"` and
`.../"data"/"market"`, the pattern `scripts/status.py:35` and
`framework/config.py:3` already use — and keep the `root` argument for tests and
diagnostics as both already do. Two lines. Then make the silence loud: have
`identifiers()` distinguish an absent root from an empty one, by returning `[]`
only when the root exists, and raising or warning when it does not. A test can
hold it without a network or a clone: `chdir` to `tmp_path`, construct on the
default, and assert the one tracked identifier is still found. This is a change
to code ADR-014 rule 1 ruled on, so the ADR needs the amendment recorded, not
just the code edited.

`AGENTS.md:102` is "When the owner rules, record the owner's own words", which
is what the headings already do.

### F-048 — The ruleset check reports that `main`'s live protections "match .github/rulesets/" after dropping three declared parameters and every bypass actor's identity from the comparison — **Medium**

**Claim.** `scripts/public_settings.py` is the only mechanical check that

### F-049 — An `xfail(strict=True)` watcher that stops failing for its own reason leaves the suite green, so the self-maintaining backlog's alarm can be silenced by editing the document it parses — **Medium**

**Claim.** `tests/test_governance_conformance.py` holds three open findings as
strict `xfail` tests and states that the backlog therefore maintains itself:
when a gap closes the test passes unexpectedly and `strict` turns the suite red.
That holds only while each test fails for the reason it names. If the document
section a test parses stops parsing, the test keeps failing for a different
reason, stays green as an expected failure, and the alarm never fires again —
including on the day the gap actually closes.

**Evidence.**
- The claim: `tests/test_governance_conformance.py:16-19` — "While the gap is
  open the test fails as expected and the suite stays green ... When someone
  closes it, the test passes unexpectedly and `strict` turns the suite red to
  say so: remove the marker, the work is done." And `:21` — "The backlog
  maintains itself. No future session has to rediscover any of this."
- Constructed, on a scratch clone, one helper at a time forced to return an
  empty collection. Fourteen document-derived helpers were tried. Eleven are
  caught — the test that uses them asserts a parsed length first and goes red.
  **Three are not**, and all three feed `xfail` tests:
  `workflow_requirements` (`:121`), `documented_workflows` (`:148`) and
  `required_metadata_fields` (`:250`). With any one of them emptied,
  `python -m pytest -q` prints `704 passed, 1 skipped, 5 xfailed` — byte for
  byte the baseline.
- The guard assertions do exist; they are simply invisible. Re-run under
  `--runxfail`, the three tests fail with a different message than they do as
  committed:

  | test | as committed | parse emptied |
  |---|---|---|
  | `test_workflow_defines_everything_the_documentation_requires` | `'Trigger' is not required of a Workflow subclass` | `expected five requirements, parsed []` |
  | `test_every_documented_workflow_is_registered` | `0 registered against 13 documented` | `no workflow documents parsed at all` |
  | `test_every_document_carries_the_metadata_block` | `123 of 123 documents do not conform` | `expected twelve keys, parsed []` |

  So each watcher *can* tell a broken parse from its own finding, and nothing
  ever asks it. All three currently fail for their stated reason — verified
  above — which is why this is a missing check rather than a present error.
- Nothing runs `--runxfail`. `.github/workflows/conformance.yml:55` runs
  `python -m pytest -q tests/test_governance_conformance.py` and `:101` runs
  `python -m pytest -q`; neither passes the flag, and no other job exists.

**Breach.** `constitution/Evidence_Standards.md:45` — "Every conclusion must
reference supporting evidence." The conclusion at
`tests/test_governance_conformance.py:21` is that the backlog maintains itself;
the mechanism supports it only for the fail→pass transition, and nothing watches
the fail→fail-differently one. Medium on the F-[042] and F-[044] precedent: a
guard that misses a reachable case, not a false claim already published.

**Failure.** *Prediction, with the most likely trigger named.*
`required_metadata_fields` parses the example block of
`docs/DocumentStandard.md` at `tests/test_governance_conformance.py:258-260` by
splitting on `"Example:"` and the rule beneath it. That document is not owner-only — the last review's F-[043]
established that `AGENTS.md:98-100` does not list it — and the finding its
watcher holds is "Document Metadata Standard Declared, Never Applied", which a
session closes by *applying* the standard, plausibly reformatting the standard
itself on the way. Rewrite that example as a list instead of a block, or rename
the heading, and the parse empties. The suite stays green that day and every day
after; when the metadata block is finally added to all 123 documents, the test
that was supposed to announce it by going red keeps xfailing instead, the marker
stays on, and the row stays open on the register. The failure mode is the one
`:14-15` already records this repository paying for once — "markers left pointing
at the old numbering was itself a recorded finding" — arriving by a different
route.

**Proposal.** Make the reason part of the assertion. `pytest.mark.xfail` takes
`raises=` and, through `pytest.raises(..., match=...)`, so does the body: assert
each watcher's failure message, or move the parse guards out of the `xfail`
tests into plain passing tests of their own — `test_workflow_readme_still_lists

### F-050 — `framework/belay.py` describes itself as the central operating system through which everything flows, and cannot be constructed in a clean checkout — **Low**

**Claim.** `Belay()` raises `FileNotFoundError` on construction in a fresh
clone, because `Librarian` hands `Registry` a working-directory-relative path
whose parent directory does not exist and `Registry.__init__` writes to it
without creating one. The module's docstring describes it as the component
everything is supposed to flow through.

**Evidence.**
- `framework/belay.py:4` — "This is the central operating system for Belay." —
  and `:6-7` — "No workflow, department, or service should directly manipulate
  the repository. Everything flows through the Belay runtime."
- Constructed, in a fresh `git clone` of the repository with the clone root as
  the working directory:

  ```
  framework/belay.py:19   self.librarian = Librarian()
  framework/librarian.py:8  self.registry = Registry(
  framework/registry.py:14    self.file.write_text("{}")
  FileNotFoundError: [Errno 2] No such file or directory:
      'memory/knowledge_registry.json'
  ```

  `framework/librarian.py:10` is the literal `"memory/knowledge_registry.json"`;
  `memory/` is not a tracked directory and `framework/registry.py:12-14` writes
  without `mkdir(parents=True)`. Were the directory to exist, the same
  relativity would put institutional memory in whichever directory the process
  started from, which is F-045's mechanism in a second module.
- The dashboard cannot see it. `scripts/status.py:102-124` imports every module
  under `framework/` and reports "will not import 0" — correctly, because the
  failure is in `__init__` rather than at import. `framework/belay.py`,
  `librarian.py` and `registry.py` are all on the untested list the same script
  prints, which is the registered P3 finding "22 Framework Modules Have No Test
  Reference".
- Related but not this: `framework/config.py` is imported by nothing
  (`grep -rn "framework.config" --include="*.py" .` returns only its own
  definition) and six of the ten directories it names do not exist, among them
  `framework/config.py:7`'s `ROOT / "knowledge"`, which differs from the tracked
  `Knowledge/` by case and so resolves nowhere on a case-sensitive filesystem.

**Breach.** None constitutional, so Low by this skill's severity table. The
registered finding "`framework/registry.py` Implements None Of The Registry
Specification" already covers `Registry.save()` replacing the whole file and the
class enforcing none of `strategies/Registry.md`'s rules; it does not cover the
constructor crash, the working-directory relativity, or the docstring's claim.

**Failure.** *Prediction, and a small one.* A session reading
`framework/belay.py:4-7` is told there is a runtime kernel and that new work
belongs behind it. It finds out otherwise on the first line it runs. The cost is
an hour and a wrong mental model of the architecture, not capital — which is why
this is Low and not Medium. It is listed because `AGENTS.md`'s own standard is
that aspiration must not be written as fact, and a docstring is where a reader
looks first.

**Proposal.** Three lines, and the cheapest correct version writes no new
feature. Either make the claim true — resolve the registry path from `__file__`
as F-045 proposes and `mkdir(parents=True, exist_ok=True)` before the write —
or make the docstring honest, by prefixing it with what
`framework/services/__init__.py:1` already says of its own neighbours:
"placeholder pending implementation". Prefer the first if `Belay` is in the
plan and the second if it is not; what should not survive is the present
combination.
