## The recommendation could not be built as it was described

This is the part worth reading, and it is a defect in how the question was put
rather than in the ruling.

The F-033 recommendation told the owner that "`Disclosure` gains a constructor
split". Building it showed that `tests/test_governance_conformance.py` asserts set
*equality* between `dataclasses.fields(Disclosure)` and the four things
`Validation/Backtesting.md` requires a backtest to document:

```python
fields = {field.name for field in dataclasses.fields(Disclosure)}
assert {name.lower().replace(" ", "_") for name in documented} == fields
```

That document is frozen by ADR-002, so **a fifth field on `Disclosure` would turn
the constitution's own validation conformance red**, and the only ways round it are
to change a frozen document or weaken the test — neither of which an agent may do.

The owner therefore agreed to a mechanism that does not exist. The substance ruled
is unaffected, and the built mechanism delivers exactly it: `Disclosure` gains an
`evidence_level` **property** returning `RESEARCH`, a frozen subclass
`FetchedDisclosure` overrides it with `HISTORICAL`, and `disclosure_from` — the
only function that takes a source and an arrived series rather than strings —
returns the subclass. Verified that this keeps the four-field assertion intact:

```
fields(Disclosure): ['assumptions', 'data_source', 'sample_period', 'known_limitations']
hand-built  -> EvidenceLevel.RESEARCH
fetched     -> EvidenceLevel.HISTORICAL
```

A side benefit that was not the reason: no new field enters the signed content, so
**every artifact's integrity hash is byte-identical to before.**

Recorded in Part 35 under "Session readings, not the owner's words", and in full in
`docs/proposals/ADR-017-grade-from-provenance-DRAFT.md`. **Same failure shape as
the two defects this session had withdrawn hours earlier**: a recommendation made
without opening the thing that constrained it.

## What changed

**First production code in this workstream.** Everything before it was tests and
documents.

- `framework/metrics/reporting.py` — `Disclosure.evidence_level` property;
  `FetchedDisclosure`; `metric_artifact` reads `disclosure.evidence_level` instead
  of hardcoding `EvidenceLevel.HISTORICAL`. That hardcoded line was F-033.
- `framework/data/fetch_record.py` — `disclosure_from` returns `FetchedDisclosure`.
- `pyproject.toml` — the three dependencies removed, with a comment recording the
  ruling and why `numpy` was not declared.
- `docs/proposals/ADR-017-grade-from-provenance-DRAFT.md` — **PROPOSED. Not
  ratified; only the owner ratifies an ADR.**

**Two existing tests changed, and both had encoded the defect.**
`test_the_evidence_is_graded_historical` asserted Level C on a fixture whose own
`data_source` reads "unit test fixture, supplied by hand";
`tests/metrics/test_drawdown.py` did the same. Both now assert Level D and say in
their docstrings what they used to claim. **These are the only two tests in 709
that the change breaks**, which is a fact about how little of the suite ever
exercised provenance.

**One test added**, in `tests/data/test_fetch_record.py`:
`test_a_derived_disclosure_grades_the_metric_historical_and_a_hand_built_one_does_not`.
It asserts the pair — derived is C, hand-built is D, and the two are identical in
every documented field. Built so that `disclosure_from` returning a plain
`Disclosure` fails it, because a guard asserted by nothing is F-019's and F-032's
shape and this session exists because of it.

## Verification, and what is missing from it

**F-036 is verified properly.** A fresh virtual environment, installed from the
edited `pyproject.toml`:

```
$ pip list | grep -iE 'pandas|numpy|jinja|dateutil'
(none present)
$ python -m pytest -q
709 passed, 1 skipped, 5 xfailed
$ python scripts/status.py     # exit 0
```

That run is the reason to trust the removal: the suite passed with none of the four
packages installed, not merely with them unused.

**F-033's suite run is incomplete, and this is stated rather than implied.** The
sandbox blocked `python -m pytest` partway through this work. What was verified
first-hand:

- The F-033 construction that produced the finding now grades `RESEARCH`
  (`validates: True`, `evidence_level: EvidenceLevel.RESEARCH`).
- A full run against the production change before the test edits: **exactly two
  failures**, both the tests named above, both asserting `HISTORICAL` on hand-built
  fixtures.
- `fields(Disclosure)` still four; the property/subclass behaviour as printed above.
- All five changed files compile.

**Not verified locally: the suite after the two test edits and the new test.** The
edits set the expected values to the two observed failures, so the expectation is
green, but an expectation is not a run. **Continuous integration on the pull
request is the first full verification of F-033**, which `AGENTS.md` point 3 makes
the gate in any case. The mutation the ADR requires — `disclosure_from` returning a
plain `Disclosure`, which must turn the suite red — **has not been run** and is
owed.
