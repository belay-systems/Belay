## The recommendation could not be built as it was described

This is the part worth reading, and it is a defect in how the question was put
rather than in the ruling.

The F-033 recommendation told the owner that "`Disclosure` gains a constructor
split". Building it showed that `tests/test_governance_conformance.py` asserts set
*equality* between `dataclasses.fields(Disclosure)` and the four things
`Validation/Backtesting.md` requires a backtest to document:

```python
fields = {field.name for field in dataclasses.fields(Disclosure)}
assert {name.lower().replace(" ", "_") for name in documented} == fields
```

That document is frozen by ADR-002, so **a fifth field on `Disclosure` would turn
the constitution's own validation conformance red**, and the only ways round it are
to change a frozen document or weaken the test — neither of which an agent may do.

The owner therefore agreed to a mechanism that does not exist. The substance ruled
is unaffected, and the built mechanism delivers exactly it: `Disclosure` gains an
`evidence_level` **property** returning `RESEARCH`, a frozen subclass
`FetchedDisclosure` overrides it with `HISTORICAL`, and `disclosure_from` — the
only function that takes a source and an arrived series rather than strings —
returns the subclass. Verified that this keeps the four-field assertion intact:

```
fields(Disclosure): ['assumptions', 'data_source', 'sample_period', 'known_limitations']
hand-built  -> EvidenceLevel.RESEARCH
fetched     -> EvidenceLevel.HISTORICAL
```

No new field enters an artifact's `content`.

**A claim here was false and is withdrawn.** This paragraph originally added that
"every artifact's integrity hash is byte-identical to before". It is not.
`ArtifactIntegrity.canonical_payload` covers `artifact.evidence_level` and each
`evidence.hash`, and `EvidenceRecord.hash` covers `level` — the grade was put
inside the hash deliberately, by ADR-005. Same artifact, fixed timestamp, built
under each commit: `f31a486f…` (Level C) before, `b21db6ed…` (Level D) after. Only
`content` is unchanged. **Consequence:** an artifact built before this change over a
hand-built disclosure no longer reproduces its stored hash. Nothing in the
repository is affected — the one committed artifact is a fetch record — but a stored
metric artifact would have been invalidated silently, and the false sentence is what
would have stopped anyone looking. Found by the independent pass.

Recorded in Part 35 under "Session readings, not the owner's words", and in full in
`docs/proposals/ADR-017-grade-from-provenance-DRAFT.md`. **Same failure shape as
the two defects this session had withdrawn hours earlier**: a recommendation made
without opening the thing that constrained it.

## Verification, and what is missing from it

edited `pyproject.toml`:

That run is the reason to trust the removal: the suite passed with none of the four
packages installed, not merely with them unused. The independent pass went further
and found nothing: all six `scripts/` run, `reports/generated/status.html` renders
well-formed at 16,118 bytes, and a walk of every module under `framework/`,
`departments/` and `scripts/` gives four import failures that are **identical with
the packages installed** — all pre-existing.

**The count in that block is stale and the reason is worth keeping.** `709` was the
*passing* count of a run that was also red — 709 passed plus 1 failed. Fixing that
failure (`9d91870`) made it **710 passed**, so the number moved while every sentence
quoting it stayed still. It was wrong in both directions across two consecutive
commits. `AGENTS.md` asks for the exact command beside a count; the lesson is that a
count copied forward stops being evidence the moment the tree moves.

## The independent pass ran, and the headline is that this does not deliver 35a

Run at 16:35 UTC on #36: **two blocking, six defects, four notes**, re-checked
against `9d91870`. Every one verified here before acting. It also discharged the
verification this record said was missing — including the mutation ADR-017 demanded:
`disclosure_from` returning a plain `Disclosure` turns the suite red on **exactly
one** test, so the new guard is asserted. The vacuity check, the conformance claim,
the round-trip, and the whole of F-036 all survived fourteen attacks.

**What did not survive is the central claim.** `disclosure_from` takes a
`DailyBarSeries`, which any caller can construct. It touches no payload, no
`content_hash`, no stored version, no fetch record. So:

```
disclosure type:  FetchedDisclosure
evidence_level:   EvidenceLevel.HISTORICAL   <- Level C
data_source:      DoltHub post-no-preference/stocks (CC BY-SA 4.0)
validates:        True
```

Eight bars typed into a file, Belay's own source, no subclass and no network.
Reproduced here byte for byte. **It is worse than F-033 in one respect:** F-033's
construction printed `data_source: I made these up`, disclosing its own
worthlessness; this one carries a real vendor's name and licence, so the grade and
the source agree and both are wrong. It is the substitution the `source` parameter
was designed to prevent, arriving through the unguarded `series` door.

The code enforces "came through `disclosure_from`". **Part 35a rules "came from a
recorded fetch". The ruling is right and the code is short of it** — so the fix is
not to soften the ruling. It is put to the owner as one question
(`docs/OperatorChecklist.md`, 2026-09-25) because it decides what a metric artifact
must carry and touches ADR-014. Nothing was implemented either way.

The overclaiming has been removed from `framework/data/fetch_record.py`, ADR-017's
Decision, Part 35's "Session readings" and this record, so no reader takes the grade
for more than "fetch-shaped".

## Part 36 — the owner closed the gap rather than letting the ruling be softened

Asked whether Level C should require the stored fetch record, the owner answered
**"yes require the stored fetch record"**. Recorded as Part 36. That is the
outcome the recommendation argued for and the opposite of the available shortcut,
which was to amend Part 35a to fit weaker code.

**What was built.** `disclosure_from` now takes a `Fetch` — the parsed series, the
stored bytes and the signed record — and takes no source and no series. It refuses
unless the record validates, its signed content carries every provenance key
`fetch_record` writes, and the bytes it names are on disk and hash to what it is
signed over. The vendor name, covered window and survivorship answer are read out
of the record, so there is no argument through which a caller can type any of them.

Verified against the implementation, not reasoned about:

```
the old attack (source= + series=)         -> TypeError: unexpected keyword argument 'source'
a Fetch forged around a signed non-record  -> ValueError: is not a fetch record
a GENUINE stored fetch                     -> FetchedDisclosure, EvidenceLevel.HISTORICAL
the stored bytes tampered after signing    -> ValueError: is not the one this record describes
the stored bytes deleted                   -> ValueError: no file at ...
the record tampered after signing          -> ValueError: integrity ... mismatch
```

**Every guard is asserted, and one test exists only because a mutation said so.**
Each of the five guards mutated alone against the committed tree: each turns the
suite red on **exactly one** test, and it is that guard's own. But the
record-validation guard first survived its own removal at 714 passing — **a guard
asserted by nothing, written by this session, whose entire subject is guards
asserted by nothing.** Reading the code would not have found it; mutating it did.
`test_a_disclosure_is_refused_when_the_record_was_tampered_with` is the result.

**A mistake worth recording, because it nearly cost the work.** The first mutation
harness ran `git checkout -- framework/data/fetch_record.py` between probes, on a
file whose implementation was not yet committed. It silently reverted the whole of
Part 36's code, and the next four probes then reported nine failures each — which
were the new tests failing against the *old* function, not mutation results. The
tell was that all four were identical. The implementation had to be rebuilt from
scratch. **Commit before mutating, or mutate a copy;** never point `git checkout`
at uncommitted work. The four "results" produced in between were discarded, not
reported.

**ADR-017 carries this rather than a new ADR-018**, since it is unratified and is
about exactly this question. Its Decision is now the ruled form, its history of
having claimed the weaker thing is kept under Law VIII, and its "Verification"
section records what has been run and what has not.

## Owner instruction, 2026-09-25: close helper sessions out when they report

Not a governance ruling and deliberately not given a Part number — a working
practice, recorded because `AGENTS.md` says a lesson living only in a provider's
memory does not exist for Belay's purposes, and this container is ephemeral.

**What the owner said**, after noticing a third falsification-pass session had
been started: *"this is getting harder to track"*, then *"yes always archive a
completed session so i know its done with"*.

**Why it needed saying.** Three passes ran on this branch — one per code state,
because fixing findings creates code nothing has reviewed, so each round needed
its own pass. That reasoning is sound and was applied without ever telling the
owner it would multiply. Two finished sessions were left showing as live, and the
owner had no way to tell those apart from one still working.

**Made worse by a tool defect worth knowing about.** A spawned session's own
`post_turn_summary` is unreliable. The first pass here summarised itself as
*"PR #36 falsification pass complete — no defects found in this read-only
audit"*. It had reported **twelve findings, two of them blocking**, on the pull
request. Anyone reading the session list rather than the pull request would have
concluded the work was clean. **The pull request is the record; a helper's own
summary is not evidence of anything.**

**Written into `AGENTS.md`** under "How work is claimed and landed", point 4, in
provider-neutral words, since Belay forbids a rule that assumes which AI service
is reading it: findings go on the pull request, a helper is closed out when it
reports, and a further pass is announced before it starts rather than after.

Both finished sessions were archived on the owner's instruction. The third was
still running when this was written and is to be archived when it reports.
